# 顺便问：复用 DSH 的按需上下文

基于已安装的 DSH `0.2.2-rc.5`，记录实现范围及后续集成建议。

## 原实现（兼容旧客户端）

`lib/client.js` 收集来源对话已完成内容的近期文本快照（最多 48k）。`lib/context-search.js` 在快照内实现 `search_snapshot`，通过额外一段 `llm.stream` 工具循环提取相关信息；`lib/index.js` 再把结果交给回答问题的子会话。较早历史检索不到，选定模型不支持工具调用时会拒绝这轮发送。

## 当前实现

- UI 保留上下文菜单，用「按需引用当前对话」取代「按需搜索近期快照」。仅当本轮发送且已选择该模式时检索，不在打开小窗时读历史。每轮捕获来源会话的已提交事件范围，避免主会话并发追加改变同一轮的证据。
- 用 `remote.session.events` 读取固定切点的有界分页（「全部对话」已使用此公开接口），只查询该侧问绑定的来源会话，不唤醒或修改主会话。用问题中的文件名、错误码、关键词本地排序，只引用少量相关已完成的用户/助手可见文本；不默认读其他会话、隐藏推理、附件或工具原始输出。将片段标记为参考数据，避免把来源文本当成指令。
- 向前扫描最多 16 页、8192 个事件、2 Mi UTF-16 文本单位，整次读取限时 10 秒。每轮最多四段，每段至多 800 UTF-16 单位；保留来源事件序号供审计。检索无命中时说明这一点，按独立问题回答；读取失败单独提示，不偷偷切到「全部对话」。省掉独立的模型搜索阶段，不要求所选模型支持工具。
- 模型需要更完整的上下文时，可用子会话专用只读工具 `btw_read_context`，按本轮已引用的事件序号补读。候选仅来自同一次固定切点读取中该事件紧邻的上一条和下一条可见消息；首次模型请求只发命中片段，候选只在工具被调用时提供。每轮最多两次，每次最多两段，重复片段合并；工具不能搜索其他会话或接收任意目标。
- 问题下方用「引用了 N 段」展示可展开的来源文本，并区分实际补读的内容。跳转原消息需先确认宿主提供稳定的公开跳转接口。

## DSH 还能提供什么

- `sessionQuery.searchEvents({ sessionId, query, filters, limit }, { signal })` 是按指定会话的全文检索接口，返回带片段的命中。已安装发行版将 SQLite 搜索挂在可选 `dsh-experimental-session-search` 组下，组内隔离 `sessionQuery`，因此不能默认 BTW 可以拿到该 provider。SQLite 首用还有语料同步成本；如要接入，需做能力探测并验证索引范围和冷启动成本，不要求普通用户另开实验功能。
- `dsh-session-reference` 支持原生会话 `@引用`，产生带来源与捕获切点的有界快照。它适合未来由用户手动指定一条会话作参考，不等同于在当前来源对话里按问题自动筛选片段。

首版验收：早于原 48k 的已提交文本可在搜索预算内命中；无命中和读取失败可区分；并发新增消息不改变当轮切点；另一会话及未授权事件始终不会进入结果；使用不支持工具调用的模型也能回答；测试使用合成会话或本地适配器。
